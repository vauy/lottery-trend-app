## 二、两个核心问题 + 根因

### 问题 1：频率K线没有上下波动起伏

**根因有 2 个（都修掉了）：**

1. **振幅公式被错误钳制**（`analysis.ts` 的 `buildFrequencySeries`）
   官方原文：「遗漏一次的线段长度为 −1，中出时线段长度为 9」，9 = 理论周期 − 1。
   旧代码 `up = Math.max(1, cycle - 1)` 把小数振幅强制成 `1`。当理论周期 ≈ 1.278（快乐8 等高概率玩法）时，
   正确振幅应是 +0.278/−1（缓涨急跌的明显波段），被钳成 +1/−1 对称锯齿后曲线失去趋势。
   → **修复**：`up = cycle - 1`（保留小数）。

2. **对频率序列做了二次累积**（`chart.tsx` 的 `candleSeries`）
   `buildFrequencySeries` 返回的**已经是累积序列**（首元素 0），但渲染时又套了一层 `cumulative()`。
   二次累积把锯齿抹成近乎单调下行的曲线（600 期里 594 点下行），图形自然没有波段。
   → **修复**：频率序列直接入 `buildCandles`；仅遗漏K线（增量序列）才 `cumulative()`。

### 问题 2：遗漏图做成了柱状图

- 重写 `OmissionChart.tsx`：主序列由 `bar` 改为 `line`（细折线连接）+ `scatter`（圆点节点带数值标签）；
  节点着色对齐参考图——**常规红、历史最大绿、零值蓝**；MA5/10/25 三条均线叠加。
- 重写 `CountChart.tsx`：由 `bar` 改为官方定义的「红色细折线 + 圆圈节点」。
- `yAxis` 显式 `min: 0, scale: false`，保证走势从 0 起、不变形。

## 四、本轮同时补齐的官方功能（此前核对的延伸）

结合官方帮助文档，本轮一并落地了此前仅写完算法、尚未接入 UI 的能力：

- **遗漏图标题统计**：对齐官方「历史最大X 平均X.XXX 理论X.XXX 当前X」格式（`chart.tsx` `omitTitle`）
- **周期K线「退期」参数**：`buildCandles` 新增 `back`，末端前推 N 期只看该段

- **遗漏和三口径**：组选 / 全胆 / 直选（`buildOmissionSums`）
- **开出遗漏**：`buildDrawOmission` / `buildDrawOmissionSeries`
- **拐点值**：`findTurningPoints`（均线局部极值）
